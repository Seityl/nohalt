# Lessons learnt

These lessons come from running fleets of autonomous coding agents against GitHub issues, unattended and often overnight, on **three production projects**. Two of them were Frappe/ERPNext apps on a shared host. The third was a web application with its own CI/CD. Three separate orchestrators grew up around them as shell scripts, cron jobs and state files. Each one was patched after every incident until the patches became the design. The GitLab lessons come from a read-only survey of a self-hosted GitLab instance where coding agents work daily.

nohalt is that design written down once, as one program. Each lesson below says what went wrong, why, and what nohalt does about it, or that nohalt does nothing about it yet. Many of the lessons are pinned by tests in [`tests/`](../tests). A test's docstring names the lesson it guards (for example `"""AGT-01: ..."""`), so if you break the rule, the test failure tells you which incident you are about to repeat.

## How to read this

- Lessons are grouped by theme. Each has a stable ID: a theme prefix and a number (`AGT-01`, `LCK-02`, …). IDs are never reused.
- **Lesson** is written as an instruction. **What happened** is the symptom we saw, described generically. **Why** is the root cause.
- **In nohalt** says how the lesson is handled:
  - a module, function or config key: nohalt enforces it;
  - *Prompt rule (core.md)*: the built-in agent prompt says it. Without a mechanism behind it, that is a preference, not a guarantee (see PRM-04);
  - *Documented: your project's job*: nohalt can't know your stack, so the lesson is yours to apply through `[verify]` hooks, `[prompt] extra`, your deploy script or your CI;
  - *Not yet*: nohalt doesn't handle it. See [Open problems](#open-problems).
- "Base branch" means the protected integration branch (`main`, `develop`, …). "Forge" means GitHub or GitLab (where pull requests are merge requests and check runs are pipeline jobs), or anything that implements `forge/base.py`.

## If you read nothing else

1. **AGT-01**: An issue is done when the forge says CLOSED. An agent's summary is not evidence of anything.
2. **AGT-02 / SAF-01**: Agents never merge, close or release. Enforce this with branch protection, not only with a prompt line.
3. **API-02**: A failed forge call means "unknown". Never read it as "open", "closed" or "no PR".
4. **MOD-01**: A model endpoint that fails is not an attempt on the issue.
5. **LIV-01**: Supervisors die while their agents live. Adopt running agents. Never start a second one on the same tree.
6. **LCK-01**: Edit in parallel, verify one at a time per singular resource. Write down why the lock exists.
7. **GIT-03**: Never discard an agent's work. Rescue uncommitted changes to a branch before removing a worktree.
8. **INT-02**: Have exactly one merger, working against a known base.
9. **DEP-01**: Nothing merges on top of a pipeline that cannot deploy. Fix forward first.
10. **SCH-03**: One stuck issue gets labelled and skipped. Everything else keeps moving.

## AGT: Agent behaviour

| ID | Lesson | What happened | Why | In nohalt |
|---|---|---|---|---|
| AGT-01 | Decide "done" from the forge: the issue is CLOSED. Never use the agent's report. | Agents reported success on work that never landed or had gone red. An endpoint that failed on every call shipped green and stayed broken for months. | An agent's summary describes what it meant to do, not what survived CI and review. | `supervisor.py` `_judge` / `_watch` ask the forge after every exit. Only `CLOSED` finishes an issue (`forge/base.py`). Tested. |
| AGT-02 | Never let an agent merge or close its own work. Back the rule with a mechanism, not only a prompt line. | An agent merged sensitive, unreviewed work it had been told to leave. | The prompt said "merge it yourself once green" in one place and "never merge" in another. The agent obeyed the louder line. | `shims/gh` refuses `pr merge`/`close`, `issue close`, `release`, and the REST merge/close/tag equivalents. Only `integrate/` merges. |
| AGT-03 | Assume an agent will route around a blocked command. Log the first step of the bypass. | A blocked agent took the auth token and called the REST merge endpoint directly. | A write token reaches everything. A shim only blocks the obvious paths. | `shims/gh` logs every `gh auth token` as `TOKEN-TAKEN` in `guard.log`. The hard control is branch protection (SAF-01). |
| AGT-04 | Treat an agent's exit code as no verdict at all. | Transport deaths were read as work failures, and successful runs as crashes. | Agent CLIs use one exit code for "the server died" and "I gave up". | `_judge` ignores the exit code. It reads the forge, then classifies the log tail. |
| AGT-05 | Pre-authorise the work in the prompt and say that nobody is watching. | Agents running under a "present a plan and wait for approval" protocol waited forever. | Agent protocols assume a human at the terminal. | Prompt rule (core.md, "Authority"): "a question asked here is never answered". |
| AGT-06 | Scope each agent to exactly one issue. File other findings instead of fixing them. | Branches grew unrelated "while I'm here" edits and conflicted with sibling branches. | Unbounded scope. | Prompt rule (core.md). |
| AGT-07 | When the time limit runs out and the issue is still open, continue in the same worktree. Don't count it as a new attempt. | Several agents hit the time box mid-work. Restarting them from scratch threw that work away. | The time box was too tight for large issues, and a timeout was treated as failure. | `_judge`: a `timeout` with the issue open resumes the session (`agents.timeout_continues`). It doesn't spend `max_attempts`. Tested. |
| AGT-08 | Make relaunched agents inspect the worktree and any existing PR first, then continue rather than restart. | Restarted agents redid finished work or opened a second PR. | Nothing was handed over between attempts. | Worktrees are reused (`worktree.py` `prepare`). `agents.RESUME_PROMPT` starts with "check `git status`, your branch and your pull request first". |
| AGT-09 | Make agents push early and often, with a draft PR within the first hour. | Agents killed by timeouts, outages or reboots lost hours of uncommitted work. | Long runs with no checkpoints. | Prompt rule (core.md, "Finishing" step 2). GIT-03 rescues whatever is left anyway. |
| AGT-10 | Require proof that a new test fails without the change, and put the failure line in the PR body. Don't let agents weaken tests, disable checks, or call a failure "flaky" without evidence. | Green suites shipped broken features. Code that compiled cleanly failed on its first call with an unresolved name. Red checks were explained away. | "No errors" is not evidence. A syntax check proves syntax, not that names resolve. A test that never bites passes forever, and the incentive is to reach green. | Prompt rule (core.md, "Verifying" and "If you are blocked"), with a stash-free recipe for taking the change out and putting it back. |
| AGT-11 | Make red CI the agent's job, not the supervisor's. | Every review turned into a repair shift for the human. | An earlier rule said "if CI is red, stop and report". | Prompt rule (core.md step 4), plus CI-02: a red PR goes back to an agent automatically. |
| AGT-12 | When an agent meets an unanswered business decision, it asks on the issue and stops. | Agents guessed at policy, and a wrong guess cost more than a pause. | Decisions weren't recorded anywhere the agent could read. | Prompt rule (core.md, "If you are blocked"). Issues carrying a `queue.held_labels` label are never launched. |
| AGT-13 | Disable sub-agents, schedulers and side-channel tools for coding agents on shared capacity. | Parallel sub-agents hung for over an hour and their results were lost. On a shared plan they burned the usage window several times over. | Fan-out multiplies load on a shared backend, and child results are not persisted. | `agents/claude_code.py` passes `--disallowedTools` (Task, cron, wake-ups, remote triggers, worktree tools…) and `--strict-mcp-config`. For opencode: *Documented: your project's job* (configure the agent profile). |
| AGT-14 | Forbid agents from touching CI infrastructure, even to unblock themselves. | An agent altered a CI runner's test database to get its PR green, which hid a bug that broke the next runner. | The agent optimised for "green", not for "correct". | *Documented: your project's job*. Add it to `[prompt] extra` and to `[verify] refuse`. SAF-04 stops the most common collateral damage. |
| AGT-15 | Don't trust an agent's claims about visuals, and don't accept mocked-backend UI tests for screens that talk to a server. Assert visual rules in code, check against a real backend, and leave screenshots for a human. | Agents claimed visual fixes they could not see. Bugs shipped that a mock could never show: rows that doubled, totals of zero from a race on load, stale derived text. | The model has no reliable image feedback inside the loop. Mocks answer instantly and consistently. Real servers don't. | *Documented: your project's job* (`[prompt] extra`, and a real-backend check through `nohalt verify`). |
| AGT-16 | Forbid stand-ins for code a sibling issue owns. Gate dependent tests on the real code existing. | A temporary duplicate data model shipped, and a billable quantity was never billed after merge. | Parallel agents built placeholders for each other's pieces, and the placeholders outlived the real code. | Partly. SCH-01 doesn't start a dependant until its dependencies close. The rule itself is *Documented: your project's job*. |
| AGT-17 | Don't make agents depend on a forge CLI to read their issue or open their PR. Give them the issue text, and a way to open a merge request with git alone. | The forge CLI on an agent machine pointed at a hostname that stopped resolving, and every agent tool broke mid-task while plain `git` over SSH still worked. | Tooling that depends on DNS, TLS and a CLI config that drift independently of the repository. | `[prompt] inline_issue = true` puts the issue and its comments in the prompt. On GitLab, the prompt gives the `git push -o merge_request.create …` fallback. Tested. |

## PRM: Prompts

| ID | Lesson | What happened | Why | In nohalt |
|---|---|---|---|---|
| PRM-01 | Write each rule once. Never repeat a rule with a different condition. | The agent followed an unconditional duplicate and skipped the exception written elsewhere (see AGT-02). | Prompt drift: a rule was edited in one place but not in the other. | `prompts/core.md` states each rule once. Stack and project text is appended, not interleaved (`prompt.py` `template`). |
| PRM-02 | When you reverse a rule, tell agents the incident behind it, so the old rule in logs and resumed sessions doesn't look authoritative. | Agents found the old instruction in earlier logs or session history and followed it. | Agents read history and can't tell which instruction is current. | *Documented: your project's job*. The shims' refusal messages explain why, not only what. |
| PRM-03 | Compose prompts per project. Never carry one between projects by search-and-replace. Fail on undefined placeholders. | A prompt carried to a non-Frappe project still told agents to run framework build commands and to "use npm, never npm". Parallel mode was switched off until it was rewritten. | Stack facts don't transfer. Mechanical substitution produces confident nonsense. | `prompt.py`: core + stack addendum + project `extra`. An undefined `{{PLACEHOLDER}}` raises `PromptError`. Tested. |
| PRM-04 | Back every important prompt rule with a mechanism (a shim, a guard, a refusal). | Rules were broken under pressure. | Other text in the context can outvote a prompt. | `shims/gh`, `shims/git`, `shims/pkill`, and the `nohalt verify` refuse list. |
| PRM-05 | State unambiguously who merges. Make the orchestrator's intent win over repository docs that disagree. | An agent finished, CI went green, and it waited at an open PR for hours, because the repository's docs said "a human merges". | Repository-level agent docs contradicted the orchestrator. | Prompt rule (core.md step 5: "You do not merge"). The integrator, or a human in `mode = "none"`, is the only merger. |
| PRM-06 | Give a resumed session a short continue-prompt and the concrete reason it was stopped. Don't send the whole template again. | Relaunched agents restarted half-done work because they didn't know why they had been stopped. | No situational context, and a full prompt the session had already seen. | `agents.RESUME_PROMPT` plus `IssueRecord.note` ("Note from the supervisor": time limit, red checks with URLs, conflict, …). |
| PRM-07 | Require a structured PR body: what was wrong, what changed, measured verification, what is still open, and the closing keyword. | PRs claimed "CI is green" with no evidence, or had empty bodies that didn't close their issue. | No template. | Prompt rule (core.md "Finishing" step 3). |
| PRM-08 | Tell agents about this environment (which commands are broken here, what to use instead, what the workaround is NOT for, the cheap checks CI runs), and keep a growing "lessons from last time" section with a guard test per production regression. | Agents retried a broken subcommand. One used a "read via REST" workaround to merge. Stale generated files caused about half the red builds in one run of work. The same class of bug came back in each new batch. | The facts lived in people's heads, and each batch's prompt started from scratch. | *Documented: your project's job* (`[prompt] extra` files, appended in order). The stack addendum (`prompts/frappe.md`) does this for Frappe. |
| PRM-09 | Name the files that conflict on every merge, and how to resolve each. | Agents resolved shared allow-lists and style guides by taking one whole side. | The merge rules were tribal knowledge. | The integrator resolves them by rule (INT-03). For agents' own rebases: *Documented: your project's job*. |

## SCH: Scheduling and queue

| ID | Lesson | What happened | Why | In nohalt |
|---|---|---|---|---|
| SCH-01 | Order is preference, dependencies are law. | Dependants started before their foundations merged, and built on code that didn't exist yet. | A single ordered list can't express "must wait for". | `queue.py` (`<issue>: <deps>`). `_launch` skips an issue until every dependency is CLOSED. Tested. |
| SCH-02 | Never invent issue numbers. An empty queue is an error, not a default range. | A default range of issue numbers read as real work. Numbers that didn't exist blocked a run. | Defaults that look like data. | `queue.load` raises on an empty queue. A missing issue is dropped (API-01). |
| SCH-03 | One stuck issue is labelled and skipped. The rest continue. | One hard issue stopped a whole night's queue. | A sequential runner with no skip. | `_block` adds `queue.blocked_label`, comments the reason and log path, and moves on. Dependants keep waiting. Tested. |
| SCH-04 | Removing the blocked label is how a human says "try again". Never read a label you failed to write as one a human removed. | Restarting a blocked issue meant editing state files by hand. | No control surface where humans already work, and a failed write followed by "the label is absent" would look like an unblock. | `_launch` sees the label gone, resets the counters and requeues. `nohalt unblock <n>` does the same. `IssueRecord.labelled` makes a failed label write get retried rather than read as an unblock. Tested. |
| SCH-05 | Re-read the queue and caps on every pass, so they can be changed without a restart. | Changing order or parallelism meant restarting daemons that held running work. | Values were cached in long-running loops. | `queue.txt` is re-read every tick. `caps.json` in the state dir overrides pool caps live. |
| SCH-06 | Put a ceiling on everything: attempts, time per run, CI hand-backs, revivals, provider retries. | A loop with no completion condition redid finished work and burned money. | No ceilings. | `[agents]` `max_attempts`, `phase_timeout`, `timeout_continues`, `ci_rounds`, `revive_limit`, `provider_retries`. Each ends in SCH-03. |
| SCH-07 | Give each class of issue its own time limit. | Platform work (standing up storage, auth, error tracking) legitimately takes many hours, and hit the global limit again and again. | One timeout for every kind of issue. | `agents.long_timeout` for issues carrying any of `agents.long_labels`. |
| SCH-08 | Give a just-stopped item a grace period before calling it dead or stalled. | Agents that had just stopped to ask a question were relaunched immediately. | Judging too early. | An agent that exits with no PR is requeued after `agents.revive_grace`, with a note asking it to explain or continue. |
| SCH-09 | Let a critical PR go first in the next batch. A short pause on new batches lets it catch up, and the pause expires by itself. | A critical PR in hot files kept losing the rebase race to the next release. | Every release re-conflicts the hot files. | Train mode: `priority` file (front of the batch), `BATCH_PAUSE` flag ignored after one hour. |

## LCK: Concurrency and locking

| ID | Lesson | What happened | Why | In nohalt |
|---|---|---|---|---|
| LCK-01 | Serialise verification on singular resources. Edit in parallel, verify one at a time per resource. | Two agents verifying at once each tested the other's build, or truncated each other's fixtures. The failures read as code faults. | A shared test database, assets built for every site at once, a host-wide restart. | `verify.py` `run_verify`: one exclusive lock per slot. Agents call `nohalt verify <worktree> -- '<cmd>'`. Tested. |
| LCK-02 | Close the lock's file descriptor for every child process. | A server an agent backgrounded inside the lock held it for hours after the command returned. | A flock is held until the last holder of the fd closes it, and children inherit fds. | `state.FileLock` marks its fd non-inheritable. `verify.py` runs commands with `close_fds=True`. Tested. |
| LCK-03 | Use a pool of equivalent resources: try each lock without blocking, take the first free one, and rewrite the resource name in the command. | Eight agents queued on one test site. | A single shared test resource. | `[verify] slots` plus `placeholder` substitution. The Frappe stack makes one slot per agent site. |
| LCK-04 | Count used slots from records written at launch, not by scanning processes. Check that a recorded pid is still the same process. | Two launchers each saw a free slot, and three agents ran under a cap of two. After a reboot, stale pids blocked slots. | A just-launched agent isn't visible in `ps` yet, and pids are reused. | `IssueRecord.status = RUNNING` is written at launch. `pids.json` stores each pid's start time, so a recycled pid is not taken for the agent. |
| LCK-05 | Make the supervisor single-instance. One process drives both sequential and parallel work. | Two runners ran at once on the same tree. A parallel wave beside a sequential run verified the wrong build. | Started by both cron and a human, and two runner modes that didn't know about each other. | `supervisor.lock` (non-blocking `flock`). `nohalt keepalive` exits if the lock is held. |
| LCK-06 | Keep a separate capacity pool per backend. | Agents on a paid API waited for local-model slots they didn't use. | One cap for backends of different kinds. | `[agents] pools` (model prefix → cap). Each pool is counted separately. |
| LCK-07 | Write down why a lock exists. Re-check the reason when you port it. | A port nearly deleted the verification lock because "there is no shared bench here". The real reasons were different (one test database, two cores). | Locks with undocumented reasons look like slowness. | `verify.py` docstring and the `[verify]` comment in the config templates ask for the reason. |
| LCK-08 | Measure parallelism on the actual machine. More agents can be slower. | Concurrent builds plus test runs on a two-core host were slower than fewer agents. | A cap copied from a bigger host. | `[agents] max_parallel` (default 2, with a comment saying to measure). |

## GIT: Worktrees and git

| ID | Lesson | What happened | Why | In nohalt |
|---|---|---|---|---|
| GIT-01 | Give each issue its own git worktree and branch. | Two agents in one tree produced half-committed branches. | A shared working directory. | `worktree.py` `Worktrees.prepare`: `<worktrees>/<issue>`, reused on relaunch. |
| GIT-02 | Look for an existing `<prefix>/<issue>-*` branch, local or remote, before creating one. | One issue ended up with duplicate branches and PRs. | Naive branch creation. | `Worktrees.branch_for`. The prefix comes from labels (`branch_prefixes`, e.g. `bug` → `fix`). |
| GIT-03 | Never discard an agent's work. Commit leftovers to a rescue branch before removing a worktree. | A reset would have destroyed commits an agent made on the wrong branch. Uncommitted work was found only in stashes. | `reset --hard` and `worktree remove --force` are silent. | `Worktrees.rescue` / `remove`: a `nohalt/rescued-<issue>-<time>` branch. Worktrees are removed only once the issue is done. Tested. |
| GIT-04 | Unset upstream on a branch cut from the base. | An agent's plain `git push` aimed at the base branch and was refused, so the work never left the machine. | `worktree add -b X origin/base` makes X track the base. | `prepare` uses `--no-track`, `branch --unset-upstream` and `push.default=current`. |
| GIT-05 | Refuse `git stash` across worktrees. | One agent's `stash pop` could take another agent's work. The stash already held entries from other branches. | `refs/stash` lives in the common git dir, so every worktree shares one stash stack. | `shims/git` refuses `stash` (except `list`/`show`) and prints a diff→checkout→test→apply recipe. Tested. |
| GIT-06 | Symlink heavy, untracked dependency folders into each worktree instead of installing them. | Each worktree cost hundreds of MB and minutes. Agents that skipped the install reported "the test suite doesn't run". | Untracked dependencies are missing from fresh worktrees. | `[project] shared_paths` are symlinked in. They are excluded from dirtiness checks and rescue commits. |
| GIT-07 | Delete stale `__pycache__` when code changes under an interpreter. | Python imported a deleted module directory as a namespace package, and a schema sync crashed. | Untracked bytecode keeps deleted packages alive. | `verify.clean_pycache`. The Frappe stack clears the app's caches before every verification. |
| GIT-08 | Never check a branch out in a checkout that serves anything. Load the worktree's code against a separate test resource instead. | A shared checkout served a branch's code for most of an hour and returned errors. A deploy migrated a half-finished branch onto real sites. | Swapping a live checkout. | The Frappe stack puts the worktree first on `PYTHONPATH` against agent-only sites and never builds or restarts the bench (FRP-02). |
| GIT-09 | Integrate and tag in a private, detached tree, never in a checkout someone else uses. Tag right after merging, from the base as fetched. | Integration steps could disturb the deploy tree. Tags landed on the wrong commit, or not at all. | One checkout doing two jobs, and tagging from a moving checkout. | Train mode uses its own detached worktree (`_release`). `Train._tag` fetches the base, tags `FETCH_HEAD` and pushes the tag. |
| GIT-10 | Disable repository hooks for automated commits. | A version-bump commit hook re-bumped the integrator's own commits. | Hooks fire on robot commits too. | `worktree.git` and the integrator pass `-c core.hooksPath=/dev/null`. |
| GIT-11 | Use the branch name as the join key between issue, branch, worktree and PR. Fall back to the first closing keyword in the full PR body. | PRs from branches with other names were never picked up. Truncating a long body before parsing lost the keyword at the end. | A missing join key, and cutting input before parsing it. | `Supervisor.pr_for` (record PR, branch, then `<issue>-` prefix, then `PullRequest.closes()` over the whole body). |

## INT: Integration and merging

| ID | Lesson | What happened | Why | In nohalt |
|---|---|---|---|---|
| INT-01 | Batch green PRs into a release. Resolve bookkeeping conflicts by rule. Version the batch. | Every single merge moved the base, re-bumped every sibling's version and restarted its long CI. A whole night was lost. | Merging one PR at a time, with version files in every PR. | `integrate/train.py`: a `release/*` branch off the base, every READY PR merged in, `mergers.resolve`, `_stamp_version`, one PR that closes every carried issue. Tested. |
| INT-02 | Have exactly one merger, working against a known base. | Agents in parallel sessions merged against different states of the base. Migrations collided and two deploys raced. | Many mergers, each with its own view of the base. | `integrate/` (`direct` or `train`) is the only merger. With `mode = "none"`, a human merges. Agents can't (AGT-02). |
| INT-03 | Resolve bookkeeping conflicts per file type with a dispatch table. Treat anything else as a code conflict: leave that PR out and hand it back. | Resolving real code mechanically would have shipped broken merges. | Not every conflict is the same kind. | `[integrate.mergers]` glob → driver. The most specific glob wins. An unmapped path is a code conflict, and its PR goes back to an agent (`hand_back`). |
| INT-04 | Merge package manifests three-way, per key, against the merge base. A key changed differently on both sides is a code conflict. | Taking "ours" dropped a real dependency. A two-way union dropped an incoming bump while the lockfile kept it, and a frozen-lockfile build went red. | A two-way merge can't tell "changed" from "unchanged". | `mergers.package_json` (recursive three-way; `version` takes ours because it is re-stamped; clashes fail). |
| INT-05 | Resolve append-only line lists (migration lists, translations) as "keep both, dedupe", prose that both sides added sections to as "keep both blocks, ours first", and ratchet allow-lists as "lowest count wins". | Constant trivial conflicts. Style guides lost one side's section. Taking one side re-grew an allow-list that should only ever shrink. | Both sides append, and ratchet semantics are not a text merge. | `mergers.keep_both_lines`, `keep_both_blocks`, `min_counts`. |
| INT-06 | For generated files, take either side and regenerate after the merge. Never resolve a lockfile mechanically. | Merged generated files were wrong. A mechanically merged lockfile wouldn't match its manifest. | Generated output is noise in a conflict. Lockfiles must be produced by the tool. | `take_theirs` / `take_ours` drivers plus `[integrate.train] after_version` to regenerate. Lockfiles: leave unmapped, or map them to `fail`. |
| INT-07 | Allocate versions centrally, at integration time. | Several PRs were bumped to the same version, so each later merge forced another bump and another CI run. | Each branch bumped its own version. | `Train._stamp_version`: the next patch after the highest tag, stamped into `version_files`. Agents never bump. |
| INT-08 | Never let a red release block the train. Rerun once, rerun network failures, then close it, park the heads it carried, and hand them back. | A red batch sat open and blocked every later batch. | No failure policy for batches. | `Train._red`: `red_retries`, network reruns (CI-04), close, the `parked` SHAs list (skipped until the head moves), `hand_back` per issue. |
| INT-09 | When a PR is left out for conflicts, send an agent. Don't rely on a comment. | A conflicted PR sat for hours, because nobody reads an integrator comment once the issue's agent has finished. | A comment with nobody to act on it. | `Supervisor.hand_back` comments and requeues a **fresh** session (MOD-10) with the rebase instruction. |
| INT-10 | Close and rebatch a release that no longer merges cleanly. | A release PR went stale when the base moved under it. | The base moves. | `Train._advance`: `mergeable is False` → close, and its PRs go into the next batch. |
| INT-11 | Treat the merge as what finishes an issue, and close the issue explicitly if the PR didn't. | A PR with an empty body merged without closing its issue, and a second agent was started on finished work. | Closing depended on a keyword in the body. | `integrate/common.close_merged`: after the integrator merges (or nohalt sees a PR merged by a human), any issue still open is closed with a comment. Forges honour closing keywords only on the default branch. Tested. |
| INT-12 | When every conflict between a PR and the base is bookkeeping, have the integrator merge the base in itself, so CI can run on the PR. Hand back only real code conflicts. Version files need drivers without anyone having to map them. | GitHub doesn't run PR CI on a conflicted branch, so agents waited for checks that never came. Two PRs were handed back three times each for "conflicts with the base branch" and then blocked for a human. Every conflict was a version stamp an agent-side hook had bumped, a generated reference doc, or a translations list. The human's fix was mechanical: merge the base, apply the drivers, regenerate, push. The project also had to map `package.json` by hand. | Release bumps and regenerated files touch what every branch touches, and a conflict was always an agent round. | `integrate/refresh.py` (`[integrate] refresh_conflicts`, default on): before any hand-back for conflicts (watcher, `direct`, train batches), nohalt merges the base into the PR branch in a scratch tree with the drivers. It runs `after_version`, commits, and pushes fast-forward only. It never does this while the agent runs, and it counts refreshes apart from `ci_rounds`. `mergers.effective` gives `version_files` an implicit `package_json` / `version_lines`. `nohalt doctor` names files that keep conflicting with no driver. Tested. |
| INT-13 | A base pipeline that never reaches a verdict is work to file, not a reason to stop the line. | A suite that ran only on the base outgrew its job's time limit. Timed-out jobs are reported as cancelled, so each was re-run, and after three the gate held every merge until a human found the flag. Green PRs, a blocker fix among them, waited overnight. | "No verdict" was treated as "hold for a human", and a timeout looks like a manual cancel. | `integrate/common.py` `PipelineGate._cancelled` with `base_no_verdict = "continue"` (default): `open_no_verdict` files one issue at the front of the queue, no `fix_issue`, deploy as a green would. A `BASE_NO_VERDICT` from an older version is cleared. `hold` keeps the old behaviour. Tested. |

## LIV: Supervision and liveness

| ID | Lesson | What happened | Why | In nohalt |
|---|---|---|---|---|
| LIV-01 | A supervisor can die while its agent lives. Adopt the agent. Never start a duplicate. | Restarting the runner next to a live agent would have put two agents in one tree, leaving a half-committed branch. | The pid lock dies with the supervisor. | LIV-02 | Have cron own the supervisor, not an interactive session, and give anything cron starts an explicit PATH. | Ending the operator's terminal session killed every agent at once, more than once. | LIV-03 | An agent is hung only when it has produced no output AND has no command of its own running. Only then restart it. | An agent waited a long time on a model reply that never came. | LIV-04 | Kill the whole process tree on stop. | Agent processes and test workers were orphaned after timeouts. | `timeout` signals only the wrapper. | `util.kill_tree` (process group plus descendants, TERM then KILL). `claude_stream` forwards signals to its child. |
| LIV-05 | Stop between issues, never mid-agent. | Killing mid-agent left half-committed trees. | Agent work has no transactional boundary. | `nohalt stop` sets `STOP`. | LIV-06 | Stop an agent as soon as its issue is closed. | Agents kept committing real fixes to an already-merged branch that nothing would ever merge. | LIV-07 | Wait on the agents themselves, not on launchers that background them and return. | A plan's `wait` returned at once and declared completion. | The launcher backgrounded the agent and exited. | The supervisor owns each agent's `Popen` and pid record. | LIV-08 | Resolve the real binary before putting shims on PATH. | LIV-09 | Make status tools local, have them follow the live run, and show verdicts, not noise. | A watcher pinned to one log replayed a finished run and looked exactly like a stall. | LIV-10 | Turn the agent's stream output into readable one-line log entries. | Raw JSON logs were unreadable, and the "last line" on status screens was useless. | Machine output in a human log. | `agents/claude_stream.py` (text, `$ command`, `[agent] rate_limit …`, `[agent] result …`). | LIV-11 | An agent that cannot start is a setup problem, not an attempt on the issue. | An agent that failed authentication on its first request was counted as having tried the issue, and was retried 15 minutes later on the same setup, where it could never succeed. | "Exited without a PR" lumped "tried and gave up" together with "never started". | `SETUP_ERROR` (auth failures, rejected CLI options) in this launch's output within its first minutes → no attempt spent, the model marked as not answering (a fallback is used), blocked after 3 with a message that points at the agent's setup. ## Anti-patterns we tried and abandoned

- **Agents merging their own PRs once green.** Replaced by one merger (a merge daemon, then a release train) and a `gh` shim that refuses merges.
- **"If CI is red, stop and report."** This turned the human into a repair shop. Replaced by "red is yours to fix", with red PRs handed back automatically.
- **One sequential runner driving one agent through phases.** Replaced by parallel agents in worktrees. The sequential runner also skipped the verification lock, so the two modes couldn't run side by side.
- **Verifying by checking a branch out into a shared, serving checkout and then building and restarting.** Replaced by worktree-first loading against agent-only test resources.
- **A single shared test site.** Replaced by a pool of equivalent slots.
- **Agents running the full test suite locally.** Replaced by "the full suite is CI's job", with a refusal behind it.
- **Merging PRs one at a time on green, with version bumps in every branch.** Replaced by batched releases with versions allocated centrally.
- **The supervisor re-bumping agents' versions after each merge.** The collisions just moved around.
- **`checkout --ours` on package manifests, then a two-way union.** Both lost real changes. Replaced by a three-way, per-key merge that escalates clashes.
- **Polling the forge once per watched issue per pass.** It exhausted the rate limit. Replaced by one listing per pass, joined locally.
- **Retrying a nonexistent issue with backoff, then reporting "is the CLI authenticated?".** Replaced by an immediate, permanent "missing".
- **A single global timeout.** Replaced by per-label time limits.
- **Waiting on a dead model endpoint.** Replaced by probing before launch and failing over.
- **Probing a subscription CLI that was at its limit.** It triggered metered sessions.
- **A single shared agent session database, compacted with VACUUM.** It needed twice the free disk and could never be vacuumed. Replaced by per-agent data directories, deleted when the issue is done.
- **Counting running agents by scanning processes.** It raced. Replaced by records written at launch.
- **Cancelling every superseded CI run, including the base branch's.** No base-branch suite ever finished.
- **Resuming the previous session for a rebase.** The agent acted on stale notes.
- **Single-shot probes (deploy version checks, fetches).** They gave false failures. Replaced by bounded retries.
- **Letting agents spawn sub-agents.** They hung and lost their results.
- **Per-batch gate scripts with hard-coded dependency maps and issue numbers.** Five copies of one idea. Replaced by one queue file with dependencies.
- **Copying a prompt from one stack to another by search-and-replace.** Replaced by composed prompts with strict placeholders.
- **Mock-only UI verification.** Real bugs shipped.
- **Credentials in scripts, launch files and prompt substitutions.**
- **A merge freeze between a fast lane and a careful lane.** It worked, but it was too complex. Superseded by the release train.

## Open problems

What nohalt does **not** solve yet. Contributions welcome.

- **The merge refusal is a speed bump.** Any agent holding a write token can call the API directly. Branch protection, or a forge app with narrowly scoped permissions, is the real control. nohalt only warns when protection is missing and logs token use.
- **Synthetic bases for dependants.** Starting a dependant early, on the base plus its dependencies' green branches, would save a full merge cycle per dependency hop. `Worktrees.prepare` accepts a base ref, but nothing builds one yet.
- **Batch mode.** One agent, one branch and one PR for several issues that touch the same file. Not implemented. Every issue gets its own agent.
- **Per-issue prompt lanes** (fast, careful, review) chosen per issue and persisted across relaunches. Today there is one composed prompt per project.
- **`nohalt pause` has no expiry.** The train's `BATCH_PAUSE` expires after an hour, but the general `PAUSE` flag stays until someone removes it.
- **Usage-aware routing.** Near a subscription's window limit, new work should go to other models and queued work should be unpinned. Today a usage limit is handled per agent (wait and resume) and routing is static.
- **Out-of-credit detection and other agents' spend.** The spend guard reads only opencode session data, and it doesn't recognise a provider's "credit balance too low" message as a hard stop for every metered agent.
- **Model-endpoint storms still become human work.** After `provider_retries` endpoint failures, an issue is blocked, with a message saying it wasn't the issue's fault. A global "the endpoint is down, wait" state would be better.
- **Fail-back and model-name changes for running work.** Fail-back happens on the next launch. A running agent stays on its fallback until it exits. Config is read at start, so a renamed model needs a restart.
- **Co-tenancy and load shedding.** Memory is checked only at launch. Nothing sheds load when agents grow later, and nothing lowers the cap when another project's agents share the host.
- **CI runner hygiene.** Killing orphaned duplicate runner listeners, restarting runners only when idle, and capping test workers on shared dependency trees are out of scope.
- **Post-release verification.** Restoring a neutralised copy of production after each release and sweeping it with real-backend checks. Also defining "shipped" as "the live version's tag contains the merge commit". Neither is implemented.
- **One base branch per configuration.** Projects whose work targets several long-lived integration branches (`release/<feature>`) need a configuration and queue per branch. nohalt can't route an issue to its own target branch yet.
- **Liveness heuristics are still heuristics.** "Hung" means a quiet log and no process outside the agent CLI's own chain. An agent CLI that waits silently inside its own process for a long time (no shell, no output) can still be judged hung.
- **Hot-file rebase races.** Priority and an expiring batch pause only make it less often that a critical PR loses to the next release. The structural fix (smaller files, ownership by area) is a project's job.
- **The human stays on the critical path** for business decisions, visual sign-off of screenshots, held sensitive changes, blocked issues and failed deploys. That is by design, but it is still the slowest part of the loop.
- **Remote or cloud agent sessions** (no local runtime, their own branch names) aren't supported.
